## Create Security groups
Total 5 SG we need.
### 1. External LoadBalancer 
- Name: `Web-ALB-SG`
- VPC: Custom VPC [3-tier-app-vpc]
- Inbound rules: 
 - HTTP - TCP[Protocol] - Portrange-80 ,Source[anywhere-IPV4]
- Create SG.

### 2. Web Tier
- Name: `Web-Tier-SG`
- VPC: Custom VPC [3-tier-app-vpc]
- - Inbound rules: 
    - HTTP - TCP[Protocol] - Portrange-80 ,Source[Custom - ALB-SG] [Through loadbalancer sg only traffic should come]. 
    - HTTPS - TCP[Protocol] - Portrange-80 ,Source[Custom - 192.168.0.0/22] [For internal traffic to the VPC]. 

### 3. App Tier
- Name: `App-SG`
- VPC: Custom VPC [3-tier-app-vpc]
- - Inbound rules: 
    - HTTP - TCP[Protocol] - Portrange-4000[Default port of react application] ,Source[Custom - 192.168.0.0/22] [For internal traffic to the VPC from App Tier]. 

### 4. Internal Load Balancer
- Name: `Internal-LB-SG`
- VPC: Custom VPC [3-tier-app-vpc]
- - Inbound rules: 
    - HTTP - TCP[Protocol] - Portrange- 80 ,Source[Custom - CIDR - 192.168.0.0/22] [internal traffic to the VPC from App Tier]. 
- Create SG.

### 5. Database Tier
- Name: `Database`
- VPC: Custom VPC [3-tier-app-vpc]
- - Inbound rules: 
    - MySQL - TCP[Protocol] - Portrange-3306[Default port of MySQL] ,Source[Custom - CIDR - 192.168.0.0/22] [For internal traffic to the VPC].

- Set up an IAM role with the necessary permissions and attach it to the EC2 instance.

We have 2 EC2 instances for App Tier and Web Tier. So we need to create 2 IAM roles. Because we have app in private subnets and we don't want to give access to the internet to the app servers.

- If you have two EC2 instances (one for the App Tier and one for the Web Tier), it is a best practice to create `separate IAM roles` for each instance, especially since your App Tier servers are in private subnets without direct internet access.
- To connect from the App servers (in private subnets) to the database, you generally have these options:
  1. Bastion Host: You can set up a Bastion Host in a public subnet, which acts as a jump box to securely access resources in private subnets.
  2. AWS Systems Manager (SSM) Agent: By installing the SSM agent on your App servers and attaching an appropriate IAM role, you can securely connect to these servers without needing a Bastion Host or opening them to the internet. The SSM agent enables features such as Session Manager for secure shell access, and may also support database connectivity through port forwarding.

- Using the SSM agent requires an IAM role with permissions for Systems Manager (such as `AmazonSSMManagedInstanceCore`) to be attached to the EC2 instances you wish to manage.

We need IAM role to work with SSM agent.

1. Click on IAM service.
2. Click on "Roles".
3. Click on "Create role".
  - Entity-type: AWS service
  - Use case: EC2
  - Permissions: `AmazonEC2RoleForSSM` why ? Because our application code is in S3 bucket and we need to access it from the EC2 instance.
4. Role name: `App-Tier-IAM-Role`
5. Create role.

We can't give external load balancer url to the user we need to provide domain name url to the user.

To create a domain name we need to create a Route 53 record.

We need to create a Web external load balancer and then we can create a domain name and then we can map the domain name to the external load balancer.

1. Careate a Target Group for the Web External Load Balancer.
- Name: `web-tier-tg-external-lb`
- VPC: VPC: Custom VPC [3-tier-app-vpc]
- health check path: /health
- Register targets: Only `Web Tier App` then include on pending group

2. Create A load blancer name: `External-Web-ALB`
- Network: `demo-vpc`
- Subnet: Public Subnet [public-1 or public-2]
- Security group: Custom SG [Web-ALB-SG]
- Listeners:
  - Protocol: HTTP
  - Port: 80
  - Target Group: `web-tier-tg-external-lb`
- Create Load Balancer.
- We will get a DNS name like this: `external-web-alb-1234567890.ap-south-1.elb.amazonaws.com`
- We will use this DNS name to connect to the application from the user.

3. Purchasing domain use route 53
- Go to route 53 and click on register domain. If  u have a domain from another provider like `go daddy` u can transfer the domain.

- After purchasing the domain, we need to create a record in route 53.
- Go to route 53 and click on create record set.
- Type: A
- Name: `www`
- Value: `external-web-alb-1234567890.ap-south-1.elb.amazonaws.com`
- TTL: 300
- Create record set.

4. Go to certificate manager and create a certificate for the domain name.
- Name: `external-web-alb-certificate`
- Domain name: `www.yourdomain.com`
- Create certificate.
- We will get a certificate ARN like this: `arn:aws:acm:ap-south-1:123456789012:certificate/123456789012`
- NOw  got to domain and create DNS record in Route 53.
- Check domain and that's it.
- Now go to the external load balancer and create a listener and map the domain name to the external load balancer.
  - Select the Protocol as HTTPS and then select the certificate and then map the domain name to the external load balancer.

4. SSL Certification and Domain Mapping
Generate an SSL certificate and apply it to the external load balancer to ensure secure communication.
Map the domain name to the external load balancer for public accessibility.
